# 玩家与随从构筑方式设计

- 文档用于记录玩家与随从角色卡构筑的设计

## 5. 玩家初始构筑设计

# 5.0 入口

- 玩家存档被标记为没有创建过角色时，存档默认为没有创建过角色，删除存档后也重置为该状态，只有完成了玩家角色构筑后才标注为创建过
- debug增加创建角色按钮，按下后可以选择创建玩家角色还是一个随从队友

## 5.1 构筑流程

新游戏或玩家重建角色时，不再直接编辑大量散字段。而是通过“构筑流程”一次性确定：

开始构筑流程后，按流程弹出窗口，完成后进入下个窗口，每个窗口都有一个按钮，可以输入prompt让AI来注入。

- 基础信息，需要玩家输入姓名（字符），年龄（int），种族（字符），身高（int单位cm），体型（字符）
- 基础能力值，27点分配法，力量，敏捷，体质，智力，感知，魅力在界面上竖直排出后面跟着当前值默认为8，玩家可以+或-来调整每个属性的数值

  - 每个属性+都会消耗1点数，当属性达到13时候开始需求为2点数来+，点数不足就无法升级。
  - 27点数全部消耗完，就不能再增加点数了
  - 这个界面AI返回每个属性的点数消耗总数不能大于27，然后后端解析为+的次数反应到前端
- 精通项

  - 不打算引入复杂的DND系统
  - 可以选择战士或者法师精通
  - 精通项目影响初始给予的法术，装备和武装-这里转awarddesign.md
- 人物立绘（AI生成）

  - 让玩家输入人物立绘的promot，然后可以点生成立绘，传送给AI生成图片返回，传给AI的信息要包含玩家的基础信息，同时需要一个生图的基础prompt和后端对图片格式的校验。
    - 基础prompt：
      - no background, no scene, no environment, no extra characters, no cropped body, no watermark, no text, no logo - 768 × 1344 - semi-realistic full body in frame, feet visible, head not cropped, centered character,no other item.
  - 也可以让玩家从本地贴入参考图片传给AI
  - 玩家可以不断重新生成直到满意为止
  - 若有贴入本地参考图片，也可以直接使用，使用本地图时，若格式不符合要求，有功能让图片裁切为固定格式。
- 立绘转外貌描述

  - 将图片传给AI，让AI输出外貌描述。
- 初始法术，初始武装，初始道具

  - AI给予初始法术，武装，道具的选项
  - 法师精通，法术十选三，战士精通，法术五选二
  - 法师精通武装只能选轻型三选一，战士精通武装可以选重型五选二，战士精通还能选武技五选二
  - 玩家选择后，就在装备到自己的装备栏，法术栏，技能栏
- 初始金币与补给

  - 初始默认50金币和3瓶Hp药水


- 随从特有的流程
- 玩家角色卡建立完成后，进入随从建立环节
- 和玩家走相同的一套流程后进入随从的特有流程
- 设定，以决定随从角色的特点，可以让AI根据设定输入返回字符进行补充，需要向AI提供之前已经填写的东西供AI参考，设定包含一下项目
  - 性格
  - 说话方式
  - 认知
  - 秘密
  - 喜好
- 原有的熟练与能力部分

## 5.2 构筑来源记录

每一项法术/武装/道具都要记录来源：

- `origin_kind = starting_build | level_up | loot | quest_reward | purchase | learned | crafted | gifted | debug`
- `origin_ref`
  - 模板包 ID / 任务 ID / 商店记录 ID / 队友 ID / Debug 记录 ID

这样后续才能做：

- 可回溯日志
- 重建角色
- 调试对比
- 死亡丢失与保留规则


# 5.3 构筑留档

- 玩家角色和随从构筑完后，需要保留在用户的文件夹中，随从就按保留的队友处理，玩家新建一个文件夹，保留所有信息包括立绘。
- 以后新建时，可以选择复用以前的角色卡，可以在原有的基础上进行调整，变成新角色。
