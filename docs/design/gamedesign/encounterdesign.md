# 遭遇设计

更新时间：`2026-03-23`

## 设计目标
- 遭遇是公开场景中的持续压力源，不再是后台自动推进的独立副流程。
- 玩家必须始终知道“现在要解决什么”，因此每个遭遇都必须有公开的 `目标(goal)`。
- 玩家不能一眼看穿遭遇真相，因此每个遭遇都必须有隐藏的 `秘密(secret)`，由 GM 与关键 NPC 持有。
- 玩家界面只看当前局势，不再看后台时间线或“最近进展”模板摘要。

## 三元结构
- `goal`
  - 公开信息。
  - 直接告诉玩家这场遭遇当前要达成什么。
  - 也会发送给队友 AI，保证队友行动围绕目标展开。
- `scene_summary`
  - 公开信息。
  - 是当前局势的唯一公开摘要。
  - 每次公开回合结束后由 AI 重新生成。
  - 不允许固定模板，不允许“围绕某某的局势继续推进”这种格式化句式。
- `secret`
  - 隐藏信息。
  - 默认只给后台、主遭遇 NPC、以及 `knows_secret=true` 的临时 NPC。
  - 玩家和队友默认看不到，只能通过信息获取、识别、洞察、调查等方式逐步接近。

## 玩家可见信息
- 主聊天列在“当前轮输出”上方显示 `遭遇目标`。
- 遭遇侧栏显示：
  - 标题
  - 目标
  - 当前局势摘要
  - 局势值 / 趋势
- 遭遇弹窗显示口径与侧栏一致。
- “最近进展”概念删除。
- “最近步骤”区域不再展示内部步骤历史，而是直接复用 `scene_summary`。

## 队友与 NPC
- 队友公开决策能看到 `goal`，不能看到 `secret`。
- 主遭遇 NPC 默认知道 `secret`。
- 临时 NPC 只有 `knows_secret=true` 时才知道 `secret`。
- 这样队友会围绕目标行动，关键 NPC 会围绕秘密组织阻碍、误导、诱导和线索投放。

## 后台推进退役
- 不再存在“玩家离场后遭遇继续自动推进”的现行设计。
- 不再支持 escape / rejoin 作为正式玩法。
- 旧存档中的 `escaped / away / background_tick` 只为兼容读取保留，不再是当前玩法的一部分。

## 遭遇结束
- 仍由局势值与终止条件共同控制。
- 常见终止条件：
  - `target_resolved`
  - `npc_leaves`
  - `time_elapsed`
  - `manual_custom`
- `player_escapes` 不再作为当前设计推荐项。

## 设计约束
- `goal` 必须具体，不允许空泛。
- `secret` 必须与目标相关，能够支撑调查、识别、洞察、搜集线索等行为。
- `scene_summary` 必须写当前可见局势，而不是抽象标签。
